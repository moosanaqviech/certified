Liquid Clustering and Predictive Optimization for the DE Professional Exam

Liquid Clustering is the Databricks-recommended layout for every new Delta table: clustering keys set with CLUSTER BY that can change without rewriting data. Predictive optimization runs OPTIMIZE, VACUUM and ANALYZE automatically on Unity Catalog managed tables. Together, with CLUSTER BY AUTO, they remove most table maintenance jobs, and the Professional exam tests when each applies.

Last updated October 2026.

Liquid Clustering, beyond the basics

  • Recommended for all new tables, including streaming tables and materialized views. It replaces partitioning and ZORDER and cannot be combined with either on the same table.
  • Up to four clustering keys. More is not better: on tables under about 10 TB, extra keys can make single-column filters slower. Choose the columns queries actually filter on.
  • Keys can change. ALTER TABLE t CLUSTER BY (a, b) takes effect for new data without rewriting the old.
  • Routine OPTIMIZE is incremental. It rewrites only data that is not yet clustered. After changing keys, run OPTIMIZE FULL to recluster existing data against the new keys.

The Professional-level trap: a team changes clustering keys on a table with two years of data, runs a routine OPTIMIZE, and expects old queries to speed up. They will not: the routine run leaves already-clustered data alone. OPTIMIZE FULL is the answer.

Predictive optimization

Predictive optimization runs three maintenance operations on Unity Catalog managed tables, using serverless jobs compute billed to your account:

OperationWhat it does
OPTIMIZETriggers incremental clustering and compacts file sizes
VACUUMDeletes data files no longer referenced, within the retention window (7 days by default)
ANALYZECollects the statistics that make data skipping work

From the Databricks docs on predictive optimization and liquid clustering, checked 23 October 2026.

It is enabled by default for accounts created on or after 11 November 2024, and Databricks has been rolling it out to older accounts. Databricks recommends it for all Unity Catalog managed tables. Two limits matter on the exam: it does not run on external tables, and it does not run ZORDER; it ignores Z-ordered files. A Z-ordered or external table still needs its own maintenance jobs.

CLUSTER BY AUTO: letting Databricks pick the keys

CLUSTER BY AUTO turns on automatic liquid clustering: Databricks chooses clustering keys from the table's query patterns and can change them as those patterns shift. It requires predictive optimization, so it is only available on Unity Catalog managed tables, and Databricks recommends it for tables whose query patterns change often.

For an existing partitioned table, ALTER TABLE t REPLACE PARTITIONED BY WITH CLUSTER BY AUTO converts it, starting from the old partition columns as keys. Databricks recommends this automatic conversion command for moving partitioned tables to liquid clustering.

Why it all comes back to data skipping

Delta stores minimum, maximum and null counts per column per file. A filter skips any file whose range cannot match. Clustering keeps related values together, so each file's range is narrow and more files are skipped. On external tables, statistics cover the first 32 columns by default, so a filter on a later column gets no skipping; managed tables under predictive optimization choose which columns to track from how the table is queried.

Signals that decide the question

Managed table, CLUSTER BY AUTO

"Reduce operational overhead", "query patterns keep changing", "no one should schedule OPTIMIZE or VACUUM".

OPTIMIZE FULL

"Clustering keys were just changed" or "clustering was just enabled on an existing table", and old data must benefit.

Manual maintenance jobs

The table is external, or still uses Z-Order. Predictive optimization will not cover it.

Leave partitioning in place

An existing, very large table with a stable, low-cardinality partition key that is not causing problems.

FAQ

What does predictive optimization do in Databricks?

It automatically runs OPTIMIZE, VACUUM and ANALYZE on Unity Catalog managed tables, using serverless compute. That keeps files compacted and clustered, removes unreferenced files and keeps statistics fresh without scheduled jobs.

Does predictive optimization work on external tables?

No. Predictive optimization runs only on Unity Catalog managed tables. External tables still need their own OPTIMIZE, VACUUM and ANALYZE jobs.

What is CLUSTER BY AUTO?

It enables automatic liquid clustering, where Databricks chooses and adjusts clustering keys from the table's query patterns. It requires predictive optimization, so it works only on Unity Catalog managed tables.

When should you run OPTIMIZE FULL on a liquid clustered table?

After enabling clustering on an existing table or changing its clustering keys. A routine OPTIMIZE is incremental and leaves already-clustered data alone, so only OPTIMIZE FULL reclusters all existing data against the new keys.

How many clustering keys can a liquid clustered table have?

Up to four. On tables under about 10 TB, more keys can slow single-column filters, so choose only the columns queries filter on most.
