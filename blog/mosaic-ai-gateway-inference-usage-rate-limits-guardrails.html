Mosaic AI Gateway Configuration: Inference Tables, Usage Tracking, Rate Limits and Guardrails

Mosaic AI Gateway is configured per serving endpoint through one ai_gateway block with five parts: an inference table that logs raw request and response JSON to Unity Catalog, usage tracking in the system.serving tables, per-minute rate limits by endpoint, user, group or service principal, guardrails on input and output, and fallbacks.

Last updated November 2026.

This post adds the configuration call, the inference table's columns with SQL that pulls one request, the usage tables joined per caller, every rate limit key, the guardrail options, and which endpoints support what.

Unity Gateway governs "model services" in Unity Catalog, moves guardrails into service policies and logs usage to system.ai_gateway.usage. The exam guide, and this post, say AI Gateway.

The full configuration for one endpoint

The Serving UI shows the AI Gateway section; the REST call is PUT /api/2.0/serving-endpoints/{name}/ai-gateway. With the Databricks SDK for Python:

from databricks.sdk import WorkspaceClient
from databricks.sdk.service.serving import (
    AiGatewayGuardrailParameters as Params,
    AiGatewayGuardrailPiiBehavior as Pii,
    AiGatewayGuardrailPiiBehaviorBehavior as PiiAction,
    AiGatewayGuardrails,
    AiGatewayInferenceTableConfig,
    AiGatewayRateLimit as Limit,
    AiGatewayRateLimitKey as Key,
    AiGatewayRateLimitRenewalPeriod as Period,
    AiGatewayUsageTrackingConfig,
)

w = WorkspaceClient()
w.serving_endpoints.put_ai_gateway(
    name="support-llm",
    inference_table_config=AiGatewayInferenceTableConfig(
        enabled=True,
        catalog_name="main",
        schema_name="genai_logs",
        table_name_prefix="support_llm",
    ),
    usage_tracking_config=AiGatewayUsageTrackingConfig(enabled=True),
    rate_limits=[
        Limit(key=Key.ENDPOINT, calls=1200, renewal_period=Period.MINUTE),
        Limit(key=Key.USER, calls=30, renewal_period=Period.MINUTE),
        Limit(key=Key.USER_GROUP, principal="support-team",
              tokens=200000, renewal_period=Period.MINUTE),
        Limit(key=Key.SERVICE_PRINCIPAL,
              principal="6f1c2a3b-0000-4d5e-9abc-1234567890ab",
              calls=300, renewal_period=Period.MINUTE),
    ],
    guardrails=AiGatewayGuardrails(
        input=Params(safety=True, pii=Pii(behavior=PiiAction.MASK)),
        output=Params(safety=True, pii=Pii(behavior=PiiAction.BLOCK)),
    ),
)

Changes apply in 20 to 40 seconds (up to 60 for rate limits). Databricks creates the inference table itself under main.genai_logs (an existing table cannot be used), and the catalog, schema and prefix change only after disabling it. Usage tracking is one flag. A fifth field, fallback_config (set to FallbackConfig(enabled=True)), retries a request that fails with a 429 or 5XX on the next served entity, up to two fallbacks, but only on external model endpoints.

Inference tables and usage tracking are billed; rate limits and fallbacks are free. The docs also advise keeping endpoint creation and CAN MANAGE with admins, so nobody bypasses limits with an ungoverned endpoint.

Which endpoints support which feature

This matters for the objective's "LLM or agent" wording. The docs' feature table and the API reference ("agent endpoints currently only support inference tables") split it like this:

Custom model endpoints get inference tables, usage tracking and QPM limits, but no TPM limits, guardrails or fallbacks. Agents deployed with agents.deploy() get inference tables automatically: _payload plus request and assessment logs, which the docs now mark deprecated.

The inference table: pull one request

ColumnWhat it holds
request_dateUTC date the request arrived (DATE). Filter on it first.
databricks_request_idDatabricks-generated ID on every request; also in the usage table.
client_request_idAn ID your app sends in the request body, so a support ticket can quote it.
request_timeTimestamp the request was received.
status_codeHTTP status the model returned (INT).
requesterUser or service principal whose permissions made the call.
request, responseRaw JSON bodies as STRING. A streamed response is aggregated across its chunks.
execution_duration_msModel inference time only, without network overhead.
served_entity_idJoins to system.serving.served_entities for model details.
sampling_fractionShare of traffic logged, 0 to 1.
logging_error_codesWhy a payload was not logged, e.g. MAX_REQUEST_SIZE_EXCEEDED.

Schema, limits and latency from the Databricks pages "Log requests and responses for serving endpoints (legacy)" and "Configure governance on model serving endpoints (legacy)", checked 7 November 2026.

SELECT
  databricks_request_id,
  request_time,
  requester,
  status_code,
  execution_duration_ms,
  request:messages                         AS messages_sent,
  response:choices[0].message.content::string AS answer,
  response:usage.prompt_tokens::int        AS prompt_tokens,
  response:usage.completion_tokens::int    AS completion_tokens,
  logging_error_codes
FROM main.genai_logs.support_llm_payload
WHERE request_date = '2026-11-03'
  AND client_request_id = 'ticket-48213';

The table name is the prefix plus _payload. request_date keeps the scan to one day, and client_request_id finds the call a user reported (without one, filter on requester and a request_time window). The : path syntax reads the JSON strings without a schema; the paths follow the chat completions format.

Three limits decide what you find. Delivery for Foundation Model API, external model and agent endpoints is best effort, typically within an hour. Payloads over 1 MiB are logged as null with logging_error_codes set. And 401, 403, 429 and 500 responses may not be logged at all. Sampling below 100% exists only on CPU custom model endpoints.

Usage tracking: tokens per caller

Usage tracking writes system.serving.endpoint_usage, one row per request with requester, status_code, input_token_count, output_token_count and a usage_context map, and system.serving.served_entities, describing each served model. Only account admins can query them by default, and records typically arrive within an hour.

SELECT
  eu.requester,
  se.endpoint_name,
  se.entity_name,
  COUNT(*)                   AS requests,
  SUM(eu.input_token_count)  AS input_tokens,
  SUM(eu.output_token_count) AS output_tokens
FROM system.serving.endpoint_usage AS eu
JOIN (
  SELECT DISTINCT served_entity_id, endpoint_name, entity_name
  FROM system.serving.served_entities
) AS se
  ON eu.served_entity_id = se.served_entity_id
WHERE eu.request_time >= current_timestamp() - INTERVAL 30 DAYS
GROUP BY ALL
ORDER BY output_tokens DESC;

This attributes 30 days of tokens to each user or service principal. Missing token counts are estimated as (text length + 1) / 4. To bill teams that share one service principal, the app sends a usage_context map in the request body (up to 10 KiB; extra_body in the OpenAI client) and you group by eu.usage_context['project'].

Rate limits: keys, QPM and TPM

Each limit is a key, a count and a one-minute renewal period: calls sets queries per minute (QPM), tokens sets tokens per minute (TPM).

KeyApplies to
endpointAll traffic. A global ceiling: once hit, every request is blocked, whatever the user limits say. The default key.
userWith no principal, the User (Default) limit each caller gets. With a user email, a custom limit for that user.
user_groupOne limit shared by all members of the named group.
service_principalA custom limit for one application ID, ranked with user limits.

Keys and rules from the SDK and REST reference for AiGatewayRateLimit and "Configure governance on model serving endpoints (legacy)"; the 429 behavior from "Apply rate limits to model and MCP services".

A custom user or service principal limit beats a group limit, and any custom limit overrides User (Default). With both QPM and TPM set, the stricter wins. A user in several groups is limited only after exceeding all of their groups' limits. An endpoint takes at most 20 limits, 5 of them group limits; none exist by default. A limited caller gets HTTP 429 Too Many Requests and should retry with exponential backoff.

Guardrails: block or mask, per phase

AI Guardrails are in Public Preview. input and output take separate settings, so Chapter 43's masking choice can differ by phase:

  • Safety (safety=True) filters content such as violent crime, self-harm and hate speech, using Llama Guard 2 8B.
  • PII (BLOCK, MASK or NONE) uses Presidio to find U.S. credit card, email, phone, bank account and Social Security numbers; detection is not guaranteed complete.

A blocked request or response returns a default message. Output guardrails do not run on embeddings models or streamed responses, batch size (or a chat request's n) cannot exceed 16, and with function calling only the final response is checked. Regions without Foundation Model APIs pay-per-token have no guardrails.

Which surface answers which question

QuestionSurface
What did the model receive and return for this call?Inference table, request and response
How many tokens did each team or app use?system.serving.endpoint_usage joined to served_entities

Exam tip: logging and metering record after the fact; only rate limits and guardrails act on the request. An option that uses the inference table to throttle a caller, or a rate limit to report spend, mixes up the two.

FAQ

What columns does a Databricks AI Gateway inference table have?

An AI Gateway inference table has request_date, databricks_request_id, client_request_id, request_time, status_code, requester, the raw request and response JSON as strings, execution_duration_ms, served_entity_id, sampling_fraction and logging_error_codes. Payloads over 1 MiB are logged as null.

Which system table tracks AI Gateway token usage?

system.serving.endpoint_usage records one row per request with the requester and input and output token counts, and joins to system.serving.served_entities on served_entity_id for model details. Only account admins can query both tables by default.

What happens when an AI Gateway rate limit is exceeded?

The caller receives HTTP 429 Too Many Requests and should retry with exponential backoff. If the endpoint-wide limit is exceeded, every request is blocked regardless of user or group limits.

Can AI Gateway rate limits and usage tracking be used on an agent endpoint?

No. Databricks documents agent endpoints as supporting only inference tables. Usage tracking, rate limits and guardrails apply on the Foundation Model API or external model endpoint that the agent calls.
