Mosaic AI Gateway and Foundation Model APIs for the GenAI Engineer Exam

Foundation Model APIs serve Databricks-hosted models from a ready-made endpoint, billed either pay-per-token or as provisioned throughput for production and fine-tuned models. Mosaic AI Gateway sits in front of those endpoints to track and govern traffic with inference tables, usage tables and rate limiting. Since August 2026 the Databricks docs call the gateway Unity Gateway; the exam guide still says AI Gateway.

Last updated October 2026.

First, the names

The Databricks Generative AI Engineer Associate exam guide (the edition live since 18 March 2026) uses Mosaic AI Gateway, short form AI Gateway, and Mosaic AI Vector Search. Databricks has renamed both in its docs since then:

  • Unity Gateway became generally available on 4 August 2026 as "the Databricks governance solution for enterprise AI, part of Unity Catalog". The endpoint-level feature the exam describes is now documented as AI Gateway (legacy) for serving endpoints.
  • Vector Search was renamed AI Search on 1 June 2026, when it gained full-text indexes that need no embeddings.

Answer with the exam guide's names; questions are written from the guide. Knowing the new names helps when you read current docs while studying.

Foundation Model APIs: two modes

Foundation Model APIs give you state-of-the-art models through Databricks-managed serving endpoints, with no deployment to maintain. Most are OpenAI-compatible, so the OpenAI client works with the endpoint name passed as the model.

Two details catch people. Provisioned throughput needs serverless compute. And pay-per-token now has a priority mode, opted into per request, which admits requests ahead of standard traffic for steadier latency at a higher per-token rate. On the exam, "steady high volume with predictable latency" and "serve our fine-tuned model" both point to provisioned throughput.

For batch work, such as scoring a whole table, the SQL path is ai_query() with AI Functions rather than calling an endpoint row by row.

A hosted model is not your agent

Keep two things apart. Calling a Foundation Model API endpoint runs only inference: you send a prompt, Databricks returns a completion. Serving your agent means logging your chain or agent with MLflow and deploying it as its own endpoint, which runs your retrieval, tools and orchestration. agents.deploy() from the Mosaic AI Agent Framework does that in one call and also creates a Review App and inference tables.

AI Gateway: three surfaces to know

The gateway is the governance and traffic layer in front of model serving endpoints, including endpoints for external providers and for agents. The exam tests three tracking surfaces, and the distinction between them is the usual question:

Inference tables

What was said. Requests and responses logged to a Unity Catalog Delta table, the raw material for monitoring, evaluation and debugging.

Usage tables

Who spent what. Token counts and request volume per endpoint and per caller, so cost can be attributed to a team, app or user.

Rate limiting

Caps requests or tokens per endpoint or per user in real time. The only one of the three that acts rather than records.

Guardrails

Safety and PII filters on requests and responses, configured once at the gateway instead of in every application.

Read the verb. "Stop a looping integration now" is rate limiting. "Show finance each team's spend" is usage tables. "Review what the model answered last week" is inference tables.

One more rule the exam enforces

An application calls a serving endpoint from its backend, with the app's own credentials. Any option that puts a Databricks token or provider API key in browser JavaScript is wrong, however convenient it looks.

FAQ

What is the difference between pay-per-token and provisioned throughput on Databricks?

Pay-per-token uses preconfigured endpoints billed by tokens consumed and is recommended for getting started. Provisioned throughput reserves dedicated capacity with performance guarantees, is recommended for production, and is required to serve fine-tuned or custom-weight models.

What does Mosaic AI Gateway do?

It governs and tracks traffic to model serving endpoints. For the exam, know its three tracking surfaces: inference tables log request and response content, usage tables track consumption per caller, and rate limiting caps traffic in real time.

Is Mosaic AI Gateway now called Unity Gateway?

In the Databricks docs, yes: Unity Gateway became generally available on 4 August 2026, and the endpoint-level feature is documented as AI Gateway (legacy). The exam guide still uses Mosaic AI Gateway, so answer exam questions with that name.

Which AI Gateway feature tracks cost per team?

Usage tables. They record token counts and request volume per endpoint and per caller, so spend can be attributed to a team, application or user.
