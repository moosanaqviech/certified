SAA-C03 Exam Domains and Weights: All 14 Task Statements Explained

The AWS Solutions Architect Associate (SAA-C03) exam has four domains: Design Secure Architectures (30%), Design Resilient Architectures (26%), Design High-Performing Architectures (24%) and Design Cost-Optimized Architectures (20%). Across the 50 scored questions that is about 15, 13, 12 and 10 questions, split into 14 task statements.

Two things stand out. Security is the single largest domain, and Domain 2 packs 26% of the exam into only two task statements, so each of those two is worth more than any other task on the paper. Domain 3 spreads 24% across five, so no single performance topic dominates.

Domain 1: Design Secure Architectures (30%)

1.1 Design secure access to AWS resources

The root user and MFA, IAM users, groups, roles and policies, AWS STS and cross-account roles, AWS Organizations with service control policies and AWS Control Tower, resource-based policies, and federation through AWS IAM Identity Center or AWS Directory Service.

1.2 Design secure workloads and applications

VPC design: public and private subnets, route tables, NAT gateways, security groups and network ACLs, VPC endpoints. Then the services around the workload: AWS WAF and AWS Shield, AWS Secrets Manager, Amazon Cognito, Amazon GuardDuty and Amazon Macie, plus Site-to-Site VPN and AWS Direct Connect.

1.3 Determine appropriate data security controls

Encryption at rest with AWS KMS and in transit with AWS Certificate Manager, key policies, key rotation and certificate renewal, backups and replication, and S3 data protection: Block Public Access, versioning and Object Lock.

Domain 2: Design Resilient Architectures (26%)

2.1 Design scalable and loosely coupled architectures

Multi-tier, microservice and event-driven designs; scaling out vs up; Amazon SQS, Amazon SNS and Amazon EventBridge; containers on Amazon ECS or Amazon EKS with AWS Fargate; AWS Lambda; Amazon API Gateway; AWS Step Functions; and purpose-built managed services.

2.2 Design highly available and/or fault-tolerant architectures

Multi-AZ and multi-Region services, Amazon Route 53 routing and failover, removing single points of failure, immutable infrastructure, monitoring with Amazon CloudWatch and AWS X-Ray, and the four disaster recovery strategies measured against RPO and RTO: backup and restore, pilot light, warm standby and active-active.

Read every DR question for the RPO and RTO first. The cheapest strategy that meets both numbers is almost always the answer. A faster strategy than the scenario needs is wrong because it costs more.

Domain 3: Design High-Performing Architectures (24%)

  • 3.1 Storage: EBS volume types, instance store, S3 throughput, and object vs file vs block storage.
  • 3.2 Compute: decoupling so tiers scale independently, EC2 Auto Scaling policies, instance families, and Lambda memory sizing.
  • 3.3 Database: read replicas, Amazon RDS vs Amazon Aurora, choosing a database type by access pattern, and caching with Amazon ElastiCache or DAX.
  • 3.4 Network: global, hybrid and multi-tier topologies, IP addressing that leaves room to grow, resource placement, and load balancer choice.
  • 3.5 Data ingestion and transformation: data lakes on Amazon S3 with AWS Lake Formation, streaming with Amazon Kinesis Data Streams, Amazon Data Firehose or Amazon MSK, AWS DataSync and AWS Transfer Family, AWS Glue vs Amazon EMR, and converting formats such as CSV to Parquet.

Domain 4: Design Cost-Optimized Architectures (20%)

  • 4.1 Storage: cost visibility with AWS Cost Explorer, AWS Budgets and cost allocation tags, S3 storage classes and lifecycle rules, right-sized volumes, the cheapest way to move data in, and hybrid storage with AWS Storage Gateway.
  • 4.2 Compute: On-Demand, Savings Plans, Reserved Instances and Spot, right-sizing with AWS Compute Optimizer, and choosing between Lambda, Fargate and EC2 on cost.
  • 4.3 Database: backup retention against RPO, DynamoDB vs RDS and serverless vs provisioned capacity, columnar storage for analytics, and migrations with AWS DMS.
  • 4.4 Network: NAT gateway placement, Direct Connect vs VPN vs internet, routing that avoids data transfer charges, Amazon CloudFront vs AWS Global Accelerator, and throttling.

Domain 4 is the lightest by weight but has the most skills listed in the guide. Its questions are often won by spotting one cost line item, such as cross-AZ data transfer or a NAT gateway processing S3 traffic, that the other options leave in place.

How to use the weights in a study plan

Give each domain study time in proportion to its weight, then shift time toward wherever your experience is thinnest. For most developers that is Domain 1 networking and Domain 4 cost; for most operations engineers it is Domain 2 decoupling. The SAA-C03 study plan turns this into weeks.

FAQ

What are the four domains of the SAA-C03 exam?

Design Secure Architectures (30%), Design Resilient Architectures (26%), Design High-Performing Architectures (24%) and Design Cost-Optimized Architectures (20%). They match four of the six AWS Well-Architected Framework pillars.

Which SAA-C03 domain has the most questions?

Design Secure Architectures, at 30%, is about 15 of the 50 scored questions. It covers IAM and multi-account access, VPC security, and data protection with AWS KMS and backups.

How many task statements are in the SAA-C03 exam guide?

Fourteen: three in Domain 1, two in Domain 2, five in Domain 3 and four in Domain 4. Each task statement lists the knowledge and skills it tests.

Is there a minimum score for each SAA-C03 domain?

No. Scoring is compensatory, so you need an overall scaled score of 720 and a weaker domain can be offset by stronger ones. The score report can include a table showing how you performed in each domain.
