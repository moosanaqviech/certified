Databricks Certified Machine Learning Professional: The Complete 2026 Guide

The Databricks Certified Machine Learning Professional exam tests whether you can run machine learning in production on Databricks. It has 59 scored multiple-choice questions in 120 minutes, costs US$200, and covers three weighted sections: Model Development (44%), MLOps (44%) and Model Deployment (12%), across 47 objectives.

The exam guide names no programming language, but its objectives and sample questions are written in Python and Spark ML, so expect to read PySpark, MLflow and Feature Engineering client code.

Who the exam is for

The Machine Learning Associate exam asks whether you can train, track and serve a model on Databricks. The Professional exam assumes that and asks what happens next: the data outgrows one node, the model has to be retrained without a person in the loop, a change has to be tested before it reaches production, and a drifting feature has to raise an alert before the business notices.

That makes it a fit for ML engineers and data scientists who already ship models and want to prove production judgment. There is no prerequisite, so you can book it without holding the Associate. The Associate vs Professional comparison covers which to take first.

The three sections and their weights

Unlike several Databricks guides, this one publishes official weights. Two sections carry 88% of the exam between them.

Weights are official. Objective counts are a line-by-line count of the guide's bullets, and question counts are the weight applied to 59 scored questions, our arithmetic and not a published figure.

Section 1: Model Development (44%)

Four sub-headings. Spark ML: when distributed training is justified, pipelines, feature transformers, tuning with CrossValidator or TrainValidationSplit, evaluators, and batch or streaming scoring. Scaling and tuning: pandas UDFs and the Pandas Function API for one model per group, distributed Optuna logged to MLflow, Ray Tune, and the vertical vs horizontal and data vs model parallelism trade-offs. Advanced MLflow: nested runs, programmatic logging and custom PyFunc models. Advanced Feature Store: point-in-time lookups, scheduled feature pipelines, Online Feature Stores, streaming features and on-demand features.

Section 2: MLOps (44%)

Half of this section's 20 objectives sit under one sub-heading: drift detection and monitoring. It covers drift tests for numerical and categorical features, profile types, building a monitor, baseline vs consecutive drift, alerts, inference tables, custom metrics, slicing and endpoint health. The other half covers the model lifecycle (see deploy code vs deploy models), unit and integration testing, environment design, Declarative Automation Bundles and automated retraining.

Section 3: Model Deployment (12%)

Five objectives: blue-green vs canary rollouts, traffic splitting across served entities on Model Serving, registering custom PyFunc models with their artifacts, and deploying and querying endpoints with the MLflow Deployments SDK or the REST API. It is the smallest section but the densest per objective: roughly seven questions over five objectives.

Product names have moved since the guide was written

The guide tells candidates to study current, non-deprecated features, and several names it uses have since changed in the Databricks documentation. Learn the current name and recognise the older one:

  • Data profiling (part of Data Quality Monitoring) is what the guide's era called Lakehouse Monitoring.
  • Databricks Online Feature Stores replace the legacy online tables the guide's objective still mentions.
  • Declarative Automation Bundles is the current name for Databricks Asset Bundles.
  • Aliases such as Champion and Challenger on Models in Unity Catalog replace the registry stages of the legacy Workspace Model Registry.

How to prepare

  • Work from the objective list. Forty-seven objectives is a finite checklist. Tick each one only when you can explain the trade-off behind it, because the questions are scenarios, not definitions.
  • Spend hours where the weight is. Sections 1 and 2 deserve close to 90% of your time, and monitoring alone is ten objectives.
  • Build one pipeline end to end. Train with a feature lookup, register to Unity Catalog, set an alias, serve it, attach a monitor. One working pipeline makes a third of the objectives concrete.
  • Finish with timed full-length mocks. Fifty-nine questions in 120 minutes is about two minutes each, and stamina matters by question 45.

Most candidates with Associate-level knowledge need 7 to 9 weeks; the study plan breaks that down week by week. Databricks publishes no passing score, so we use 70% on timed practice as our own target, and 85% on full mocks as the readiness bar. Both numbers are our guidance, not an official threshold.

FAQ

How many questions are on the Databricks Machine Learning Professional exam?

The exam has 59 scored multiple-choice questions and a 120-minute time limit. Databricks may add a small number of unscored questions that are not identified, with the extra time already included.

How much does the Databricks Machine Learning Professional exam cost?

The registration fee is US$200 per attempt. The certification is valid for two years, and recertifying means passing the current version of the exam again.

Do I need the Machine Learning Associate before the Professional?

No. The Machine Learning Professional exam has no prerequisites, so you can book it directly. Databricks recommends at least one year of hands-on experience with the machine learning tasks in the exam guide.

What is the passing score for the Databricks Machine Learning Professional exam?

Databricks does not publish a passing score for this exam. A practical target is 70% or more on timed practice exams and 85% on full-length mocks, which is our guidance and not an official threshold.

What topics does the Databricks Machine Learning Professional exam cover?

It covers three sections: Model Development at 44%, MLOps at 44% and Model Deployment at 12%. In practice that means Spark ML, distributed training and tuning, advanced MLflow and Feature Store, testing and environments, drift monitoring, and Model Serving rollouts.
